# 项目接手手册设计

日期：2026-07-25

## 1. 目标读者

手册面向第一次接手 `work_order_process` 的初级 Python 程序员。读者可能了解
Python、SQL 和命令行基础，但不了解帮我吧工单 API、项目数据模型、ERP 分摊规则和
生产运行方式。

文档目标是让读者能够：

1. 在本地正确安装依赖并完成只读验证。
2. 理解工单、客户、联系人、人员、台账、ERP 和营收数据的完整流向。
3. 根据场景选择正确命令，识别命令是否调用 API、写数据库或覆盖快照。
4. 找到主要模块、类和函数，理解其输入、输出、副作用和调用关系。
5. 完成常规开发、测试、数据导入、生产检查和故障定位。
6. 在修改代码后同步更新对应文档，避免手册逐渐失真。

## 2. 交付物

docs/project_handover_guide.md

现有专题文档继续作为权威细节来源，不复制全部字段字典和历史设计过程：

## 3. 内容来源和准确性

手册内容按以下优先级核对：

1. 当前 Python 代码、SQL、TOML、JSON、systemd 和脚本。
2. `work_order_process --help` 与 `erp-merge --help` 的实际输出。
3. 当前自动化测试所表达的行为约束。
4. 现有专题文档。
5. 历史设计文档只用于解释背景，不覆盖当前代码。

手册不得包含：

- 真实 API、MySQL、SSH 账号或密码。
- 容易变化的生产数据量和临时文件名，除非明确标记为示例。
- 已删除的脚本、命令、参数或文档链接。
- 未经代码或测试确认的业务规则。

服务器地址、账号权限和运行状态属于部署时信息，手册只说明配置位置和核对方法。

## 4. 文档结构

正式手册按“先运行、后理解、再维护”的顺序组织。

### 4.1 快速接手

- 项目用途和当前能力。
- 技术栈、Python 与 `uv` 要求。
- 只读的首次检查命令。
- `.env` 创建方式和最小配置。
- API、MySQL、测试和 CLI 的验证顺序。
- 新手第一天不应执行的危险命令。

### 4.2 架构与数据流

- 项目目录树。
- 工单 API 数据流。
- 客户与联系人同步流。
- ERP 合并、分摊、临时表校验、事务发布和数据库导出流。
- 台账快照导入流。
- ERP 到月度营收汇总流。
- 定时同步、日志和备份流。

使用 Mermaid 表达系统边界、模块调用和主要数据库关联。图中文字同时使用业务中文和
代码英文名。

### 4.3 配置与依赖

- `pyproject.toml` 默认、开发和 ERP 依赖组。
- `.env.example` 的全部环境变量。
- `config/erp_merge_rules.toml`、时间指标和工作日历配置。
- 本地与生产环境差异。
- 凭据、文件权限和 Git 安全约束。

### 4.4 命令参考

覆盖两个入口：

```text
uv run --all-groups work_order_process ...
uv run --all-groups erp-merge ...
```

每个命令记录：

- 用途。
- 必要参数和常用可选参数。
- 可直接运行的 PowerShell 示例。
- API、文件和数据库依赖。
- 输出文件或修改的数据表。
- 是否写库、是否覆盖、是否可重复执行。
- 常见失败原因和执行后验证 SQL。

命令按风险分为：

- 只读。
- 只写本地文件。
- 数据库新增或更新。
- 数据库结构或删除类危险操作。

### 4.5 模块和函数参考

按模块记录所有类和模块级函数。每个条目至少包含：

- 函数或类签名。
- 一句话职责。
- 主要输入和返回值。
- 外部依赖。
- 文件、网络或数据库副作用。
- 可能抛出的业务异常。
- 主要调用者或调用链位置。

函数分级：

- **入口函数**：CLI、定时任务和脚本入口。
- **核心业务函数**：API、解析、同步、ERP、营收和数据库写入。
- **重要内部函数**：影响事务、映射、清洗、分区和错误处理的私有函数。
- **简单辅助函数**：在模块表中列出用途，不为每个函数重复大段示例。

这能覆盖“各个函数”，同时避免文档被格式转换等细小辅助函数淹没。

### 4.6 数据库和业务流程

- 数据域和表用途。
- 主键、唯一键、分区键和快照日期。
- 工单、客户、联系人、人员、台账、ERP、营收之间的逻辑关联。
- ERP 年度分摊和倒签调整。
- 月度营收四组指标。
- 常见单表、关联、质量检查和金额核对 SQL。

完整字段字典和大段 SQL 链接到 `docs/database_usage.md`，手册保留理解流程所需的
关键字段。

### 4.7 开发、测试和生产运行

- 推荐修改流程和最小验证命令。
- 测试目录与模块对应关系。
- GitHub Actions 验证内容。
- `daily_runner` 三类定时任务。
- systemd、logrotate、备份 timer 和恢复演练。
- 发布前检查、发布后只读验收和回滚原则。

### 4.8 排障和维护

- API 认证、HTTP 错误和异常 JSON。
- MySQL 连接、权限、分区和重复数据。
- Excel 表头、公式值、数值和日期问题。
- ERP 快照发布失败和营收全零保护。
- 调度器任务失败与日志定位。
- 文档维护矩阵：某个代码文件变化后应更新哪些章节。

## 5. 命令示例规则

本地命令默认采用 Windows PowerShell，生产命令采用 Linux Bash，并明确标注代码块。

示例使用占位路径和占位账号。所有写库命令前增加“确认数据库和快照日期”的检查步骤，
危险命令 `mysql-drop-tables` 单独标红说明，不与普通初始化命令混排。

命令中的入口名称以 `pyproject.toml` 为准，不使用旧项目名或历史脚本名。

## 6. 图表设计

手册包含三张 Mermaid 图：

1. 系统组件和外部依赖图。
2. 工单、ERP、台账和营收数据流图。
3. 主要数据库表逻辑关联图。

图表用于理解，不替代可复制的文字步骤。每张图后提供文字解释，保证 Markdown
渲染器不支持 Mermaid 时仍可阅读。

## 7. 验证方式

完成手册后执行：

1. 运行两个 CLI 的 `--help`，逐项核对命令和参数。
2. 从源码提取类和模块级函数名，与模块参考章节比对。
3. 检查所有 Markdown 本地链接存在。
4. 检查文档没有已知真实凭据、root 示例和已删除路径。
5. 执行完整测试。
6. 执行 `git diff --check`。

验收标准：

- 新手从手册可完成环境安装和只读验证。
- 全部 CLI 子命令均有说明。
- 每个 `src/work_order_process` 模块均有职责说明。
- 所有类和模块级函数均被索引，核心函数有详细解释。
- 写库、覆盖和删除行为均有清晰风险提示。
- 数据库、ERP、营收、调度和生产运行均有端到端步骤。
- 所有命令、链接和文件名与当前仓库一致。

## 8. 维护原则

手册顶部记录“最后核对提交”，而不是仅记录日期。修改以下内容时必须同步手册：

| 变更位置 | 需要更新 |
|---|---|
| `pyproject.toml`、`cli.py`、`erp_merge/cli.py` | 环境和命令参考 |
| `.env.example`、`config/*` | 配置参考 |
| `src/work_order_process/*.py` | 模块和函数索引 |
| `sql/*.sql`、`mysql_storage.py` | 数据库和查询章节 |
| `daily_runner.py`、`deploy/*`、`scripts/backup_mysql.sh` | 生产运行章节 |
| ERP、营收业务规则 | 数据流、计算规则和核对 SQL |

专题文档仍负责完整字段与专项规则；接手手册负责入口、流程、风险和导航。
